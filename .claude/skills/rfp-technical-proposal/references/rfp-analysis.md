# Step 1 — Deconstructing the RFP into the Proposal Plan

Before any slide is written, transform the RFP/scope-of-work into a **Proposal Plan** — a
structured brief that every later section consumes. Do this completely and write it down
(scratchpad file `proposal-plan.md`); every downstream section playbook references it.

## 1. Extract the hard facts (verbatim, with page refs)

From the RFP capture:

| Field | What to capture | Where it lands in the deck |
|---|---|---|
| الجهة (client entity) | Exact legal Arabic name + logo | Cover, letter addressee, every "الأمانة/الجهة" reference |
| اسم المشروع | Exact project name as written in the RFP | Cover, letter subject, footers, every title that names the project |
| نوع الطلب | RFP / RFI / كراسة الشروط والمواصفات | Letter opening paragraph wording |
| الأهداف | Stated objectives, verbatim list | Exec summary slide 1; PoV argument; approach tracks |
| نطاق العمل | Scope items / work streams / requirements | Approach tracks & detailed methodology slides |
| جدول الكميات (BoQ) | Deliverables with quantities/frequencies | The BoQ-mapping slide in the approach; Gantt markers |
| المدة الزمنية | Contract duration and any phase durations | Approach overview title ("خلال مدة زمنية تقدر بـX"), Gantt |
| فريق العمل المطلوب | Required roles, seniority, qualifications, certifications, headcounts | Team structure, CV selection & retitling |
| معايير التقييم | Evaluation criteria and weights | Ordering of credentials; emphasis throughout; the credentials summary matrix columns |
| الخبرات المطلوبة | Required similar-project experience (sector, geography, count, recency) | Credentials shortlisting filter |
| المخرجات | Named deliverables per scope item | المخرجات والنتائج sidebars of methodology slides |
| متطلبات الحوكمة | Reporting cadence, committees, quality gates | Launch-phase slides (آلية إدارة المشروع، خطة إدارة الجودة) |
| اللغة | AR / EN / bilingual | Whole-deck language; these references assume AR |

**Never paraphrase the project name or client name — they must match the RFP exactly,
everywhere they appear.**

## 2. Derive the strategic read (this is where the thinking happens)

Answer in writing:

1. **What is the client really buying?** Behind the scope items there is one underlying
   anxiety (e.g. deck 1: "the leadership needs continuous decision-grade studies";
   deck 2: "the sector can't guarantee output quality at its new scale"). One sentence.
   This becomes the spine of the الملخص التنفيذي and وجهة نظرنا.
2. **What context makes this urgent now?** Vision/strategy programs, growth numbers,
   institutional changes. Feeds the PoV context funnel.
3. **What 3 enablers or challenges frame the need?** Compress the scope into exactly **3**
   (the house pattern is ALWAYS 3 drivers; only the work areas vary 3–5) client-side gaps:
   - If the project is *opportunity-driven* (strategy, studies, growth) → frame as
     **ممكنات (enablers)**: "ولمواكبة التطور، تحتاج الجهة إلى 3 ممكنات رئيسية".
   - If the project is *problem-driven* (quality, performance, operations) → frame as
     **تحديات (challenges)**: "3 تحديات تشغيلية تواجه {الجهة}".
   Each must be provable with data (an evidence slide follows each one).
4. **What work areas answer them?** 3–4 مجالات رئيسية that bridge from the
   enablers/challenges to the approach tracks. The mapping enabler→area→track must be
   airtight — an evaluator should be able to trace every scope item through this chain.
5. **What does the client's own strategy say?** Find the client's published strategy,
   Vision 2030 linkages, transformation programs. At least 1–2 PoV slides must show we
   know *their* strategy documents, org structure, and ecosystem.
6. **Which Deloitte-style methodologies fit?** Map each work area to framework families
   (see `appendices.md` §1): strategy design, policy cycle, TOM, performance
   management, PMO, change/knowledge transfer, scenario planning…
7. **Key messages** — write the 4–6 win themes that the letter bullets, exec summary, and
   PoV proof slides will all repeat (deep local knowledge; leadership-support track record;
   multidisciplinary local+global experts; alliances; sustainable-partnership commitment).

## 3. Design the approach skeleton

- Convert scope items into **N tracks (مسارات)** or **N phases (مراحل)**:
  - Parallel/continuous service streams → **مسارات عمل** (deck 1: 4 tracks / 9 months).
  - Sequential build-and-handover work → **مراحل** (deck 2: 6 phases / 18 months).
  - Always prepend **المسار/المرحلة صفر: الإطلاق** (launch) — alignment workshop, success
    criteria, project charter.
  - Always end with (or include) a **تمكين مؤسسي / نقل المعرفة** stream — knowledge
    transfer is a fixed house theme.
- Name each track with a noun phrase lifted from the RFP's own vocabulary.
- For each track draft: objective (1 line), 4–8 sub-tracks (X.1, X.2…), activities
  (verb-first bullets), deliverables (map 1:1 to the BoQ), and page count
  (1–3 slides per track → "(1/3)" pagination).

## 4. Compute the deck budget

Target the reference proportions (≈270–290 slides total, but scale to RFP size; keep the
*ratios* even when smaller):

| Section | Deck 1 actual | Share of core |
|---|---|---|
| الملخص التنفيذي | 3 (divider + 2) | fixed |
| وجهة نظرنا | 37 | ~50% of the core body |
| النهج الذي سنتّبعه | 19 | ~30% |
| الجدول الزمني | 2 (divider + Gantt) | fixed |
| فريق العمل | 6 | fixed-ish |
| ملحق: ملفات تعريف الفريق | ~9 | 1 CV/slide |
| ملحق: ملفات تعريف الخبراء | ~12 | 1 expert/slide |
| ملحق: خبراتنا | ~80 | summary matrix + 1 credential/slide |
| ملحق: أطر العمل والمنهجيات | ~60 | reusable library selection |
| ملحق: نبذة عن ديلويت | ~12 | fixed library |
| ملحق: الشروط والأحكام | ~12 | fixed library |
| ملحق: المستندات القانونية | ~10 | fixed library |

A leaner proposal keeps the same order and simply shrinks PoV/credentials/frameworks.

## 5. Build the retrieval shopping list

From the plan, write explicit queries for the reference library (see
`reference-library.md`):

- **Credentials**: sector + service-type + geography filters; the evaluation-criteria
  matrix column headers; target counts (local ≥ global; both decks ran ~60 local + ~10 global).
- **CVs**: one candidate per required role in the RFP (partner, exec director, manager,
  senior consultants, consultants) + experts covering every domain the RFP names.
- **Frameworks**: one framework family per work area + the fixed launch/PMO/knowledge-transfer set.
- **Boilerplate**: letter skeleton, About Deloitte, T&C, legal certificates, divider art.

## 6. Sanity checks before building

- Every RFP objective appears in: exec summary ✚ at least one PoV slide ✚ exactly one
  approach track ✚ the Gantt.
- Every BoQ line has a deliverable in a methodology slide **and** a marker on the Gantt.
- Every required role in the RFP has a named person with a CV slide.
- Every evaluation criterion is answerable by pointing at a specific slide.
- Team size proposed = team size priced (deck 1 slide 47 explicitly reassures on this).
